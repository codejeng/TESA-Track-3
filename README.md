# Track 3 Agent: โครงเตรียมไว้ก่อนวันแข่ง

Agent ขายเมล็ดกาแฟแบบซองปิด สำหรับ TESA Top Gun Rally ครั้งที่ 20 (Track 3 Next Gen Market)
เขียนก่อนได้เอกสาร API จริง ส่วนที่ยังไม่รู้จึงแยกไว้ให้แก้ได้ในไม่กี่จุด

## โครงสร้าง

| ไฟล์ | หน้าที่ | ต้องแก้พรุ่งนี้ไหม |
|---|---|---|
| `market_client.py` | ยิง API ตลาด แปลง JSON → models | **แก้แน่นอน**: `ENDPOINTS`, `parse_*`, `build_offer_payload` |
| `pricing.py` | สูตรราคามาตรฐาน, ตรวจสเปก, guardrail, กลยุทธ์ rule-based | **แก้** `standard_price()` เป็นสูตรจริง |
| `llm.py` | prompt + เรียก LLM กลาง + parse JSON | ปรับ `SYSTEM_PROMPT` หลังวันที่ 17 |
| `config.py` / `.env` | URL, key, ค่ากลยุทธ์ | ใส่ค่าจริงใน `.env` |
| `agent.py` | ลูปหลัก | ปกติไม่ต้องแก้ |
| `models.py` | โครงสร้างข้อมูลกลาง | ไม่ต้องแก้ |
| `mock_market.py` | ตลาดจำลอง + LLM ปลอม ไว้ทดสอบ | ไม่ต้องแก้ |

## เริ่มใช้งาน

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

ทดสอบกับตลาดจำลอง (เปิด 2 terminal):

```bash
python mock_market.py --rounds 6 --round-seconds 15     # terminal 1
python agent.py                                         # terminal 2 (โหมด llm กับ LLM ปลอม)
python agent.py --rule                                  # หรือไม่ใช้ LLM
```

ดูคะแนนในตลาดจำลอง: `curl -H "X-Team-Key: team-demo" http://127.0.0.1:8000/score`

## หนึ่งรอบ agent ทำอะไร

1. `GET state` → รอบไหน ตลาดเปิดไหม ฤดูอะไร
2. `GET results` ของรอบที่ปิดไปแล้ว → เก็บราคาที่ผู้ซื้อจ่ายจริง และผลซองของเราใน `Memory`
3. `GET orders` + `GET inventory` → คำนวณราคามาตรฐานถ้า API ไม่ได้ให้มา
4. `rule_plan()` → แผนพื้นฐาน
5. ถ้าโหมด llm: ส่งสถานการณ์ย่อ + แผนพื้นฐานให้ LLM ปรับ
6. `validate()` → ตัดซองตกสเปก, จำนวนเกินของที่มี, ราคาต่ำกว่า floor, เกินโควตาต่อรอบ
7. `POST offers` → ยื่นซอง แล้วเขียนทุกอย่างลง `logs/agent_log.jsonl`

ถ้า LLM ล่ม ช้า หรือตอบไม่เป็น JSON → ใช้แผน rule ทันที รอบนั้นไม่หลุด

## กลยุทธ์ rule-based ตอนนี้

- **ราคาขั้นต่ำ** = 82% ของมาตรฐาน (ตลาดกลางรับ 80% ตอนจบเกมอยู่แล้ว ขายต่ำกว่านั้นขาดทุน)
- **ยังไม่มีข้อมูล** → เริ่มที่ 106% ของ min(มาตรฐานล็อตเรา, ระดับราคาของผู้ซื้อ)
- **มีข้อมูลแล้ว** → ตั้งต่ำกว่าราคาสูงสุดที่ผู้ซื้อเจ้านั้นจ่ายจริงรอบก่อนเล็กน้อย ปรับตามฤดูที่เปลี่ยน
- **ผลรอบก่อน**: ขายหมด → ขยับขึ้น 2% ไม่ได้เลย → ลด 4%
- **รอบสุดท้าย** → ยอมลงไปที่ราคาต่ำสุดที่เคยขายได้
- **จัดสรร**: เรียงคู่ (ล็อต, ผู้ซื้อ) จากราคา/มาตรฐานสูงไปต่ำ ขายเร็วกว่าแบ่งเท่าๆ กันเล็กน้อย (`PACE`) ยื่นให้ผู้ซื้อเจ้าเดียวไม่เกิน 60% ของที่เขาต้องการ

ทุกค่าปรับได้ใน `.env` โดยไม่ต้องแก้โค้ด

## เช็กลิสต์วันที่ได้รายละเอียดจริง

- [ ] path ของ API และชื่อฟิลด์ทั้งหมด → `market_client.py`
- [ ] header/วิธียืนยันทีม → `TEAM_HEADER`, `TEAM_KEY`
- [ ] สูตรราคามาตรฐาน (เกรด, เมล็ดเสีย, ขนาด) → `pricing.standard_price()`
- [ ] เกรดเลขน้อยดีกว่าหรือเลขมากดีกว่า → `GRADE_LOWER_IS_BETTER`
- [ ] โควตาต่อรอบจริง → `MAX_SACKS_PER_ROUND` (ถ้า API ไม่ได้บอก)
- [ ] ข้อความฤดูที่ระบบใช้ → `season_high_words` / `season_low_words` ใน `config.py`
- [ ] URL, ชื่อโมเดล, key ของ LLM กลาง และ rate limit → `LLM_*`
- [ ] โครงสร้าง repo และ workflow ของ CI ที่กรรมการกำหนด
- [ ] ถ้ากรรมการให้ starter code: ใช้ client ของเขา แต่ให้คืนค่าเป็น `models.py` แล้วเสียบ `pricing` + `llm` ของเราต่อ
- [ ] รัน `python agent.py --dry-run --once` กับตลาดจริงก่อน เพื่อดูว่า parse ข้อมูลถูกไหม

## หลังวันที่ 17 (วันขายด้วยมือ)

จดนิสัยผู้ซื้อแต่ละเจ้า เช่น ซื้อที่กี่ % ของมาตรฐาน ช่วงฤดูไหนจ่ายแพง แล้วเอามาใส่:
- ปรับตัวเลขใน `.env` (`START_MARKUP`, `STEP_*`, `UNDERCUT`, `PACE`)
- เขียนสิ่งที่สังเกตได้สั้นๆ ลง `SYSTEM_PROMPT` ใน `llm.py` (ภาษาอังกฤษ ประหยัด token)

`logs/*.jsonl` เก็บทุก prompt, ทุกซอง และทุก feedback ไว้ย้อนดูได้

## ข้อควรระวัง

- LLM กลางมี context แค่ ~4K tokens: prompt ที่ส่งเป็น JSON ย่อ ประวัติแค่ 2 รอบล่าสุด และตัดเหลือ 1 หรือ 0 รอบถ้ายาวเกิน
- อย่าให้ LLM คิดเลขเอง: ราคามาตรฐาน, floor และโควตาคำนวณในโค้ดหมด LLM แค่เสนอ แล้ว `validate()` ตรวจทุกครั้ง
- `mock_market.py` เป็นค่าสมมติทั้งหมด (เพดานผู้ซื้อ, คู่แข่ง, ฤดู) ผลคะแนนในตลาดจำลองไม่ได้บอกว่าจะเก่งในตลาดจริง ใช้ไว้ทดสอบว่าโค้ดไม่พังเท่านั้น
